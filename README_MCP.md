# MCP-сервер mitsu-kkl: Claude читает ЭБУ сам

`mcp_server.py` — это MCP-сервер (stdio). Через него Claude (Desktop или Claude Code) сам подключается к
ЭБУ двигателя по кабелю VAG KKL, снимает дампы, пишет и анализирует логи и ведёт карту PID для
**этой** машины. Сервер построен на модулях `kkl/` (link, proto, livepoll, sim) и логику протокола
не дублирует.

Машина: **Mitsubishi Colt CJ4A 1999, 4G92 1.6 SOHC, АКПП, ЭБУ MD353925, без лямбда-зонда (open loop).**
Готовой карты PID для этого ЭБУ нет, мы её строим сами. Карта автора (Eclipse 4G63, ECU ID `E4 3A`) для
Colt — только **гипотеза**.

## Безопасность (зашита в коде MCP, параметрами не отключается)

- На K-линию уходят только запросы чтения MUT `00–BF` и `FD–FF`. Запрос `C0–FC` (`0xCA` стирает коды,
  `F1–FC` включают исполнительные механизмы и отсекают форсунки) отклоняется дважды: сначала при разборе
  аргументов, потом ещё раз на уровне записи в кабель (`GuardedDevice`), независимо от библиотеки.
- Стирания кодов (`0xCA`) в MCP нет совсем.
- Одновременно открыта только одна сессия с кабелем. Пока сессия простаивает, сервер раз в 2 с шлёт
  запрос `FE` (ЭБУ рвёт сессию примерно через 10–15 с тишины). Если сессия всё же пропала, следующий запрос
  сам заново выполняет 5-бодовую инициализацию. `disconnect` закрывает COM-порт / D2XX.
- Имена и формулы PID пишутся только в `profiles/colt_cj4a_md353925.csv`, а журнал изменений с
  доказательствами — в `profiles/colt_cj4a_md353925_notes.md`. Файлы автора (`pid_definicje.csv`,
  `dtc_definitions.csv`) сервер только читает.

## Установка на Windows

1. **Python 3.11+** с [python.org](https://www.python.org/downloads/windows/). При установке поставьте
   галочку *Add python.exe to PATH*. Полный путь к Python покажет команда `where python`, он понадобится
   для конфига Claude Desktop.
2. **Код:**
   ```
   cd C:\
   git clone -b colt-mcp https://github.com/kapyctnik-ai/mitsu-kkl.git
   cd C:\mitsu-kkl
   python -m pip install -r requirements-mcp.txt
   ```
   Без git: на GitHub выберите ветку `colt-mcp` → *Code* → *Download ZIP* и распакуйте архив в `C:\mitsu-kkl`.
3. **Драйвер FTDI (D2XX + VCP):** установщик *CDM … WHQL Certified* (setup executable) с
   [ftdichip.com/drivers](https://ftdichip.com/drivers/). Он ставит `ftd2xx.dll`: через неё сервер
   управляет чипом FT232RL напрямую (break, bit-bang, задержка 1 мс).
   Если работаете через COM-порт (`--iface serial:COM5`), выставьте в *Диспетчере устройств* →
   *Порты* → *USB Serial Port* → *Параметры порта* → *Дополнительно* → *Время ожидания (Latency Timer)* = 1 мс.
4. **Проверка без машины:**
   ```
   python -m pytest tests -q                       # 25 тестов на симуляторе, около 50 с
   python kkl_probe.py info                        # видит ли система кабель (ничего не отправляет)
   ```

## Кабель и разъём

Кабель VAG KKL 409.1 (FT232RL + LM393) с переключателем линии.

- **Переключатель кабеля — в положение «7»** (K-линия = контакт 7 OBD).
- **Перемычка pin 1 → pin 4** (масса) в разъёме OBD. Кабели VAG контакт 1 не используют, поэтому нужен
  отдельный провод, лучше с выключателем. Без массы на pin 1 этот ЭБУ молчит.
- Включите зажигание. С массой на pin 1 «check engine» обычно начинает мигать кодами: это нормально, ЭБУ
  в режиме диагностики. После работы перемычку снимите.
- Контакты: 7 = K-line, 16 = +12 В (питание кабеля), 4/5 = масса, 1 = режим диагностики.

Первая проверка у машины: `selftest` (из Claude или `python kkl_probe.py selftest`).
`OK` — кабель запитан и слышит своё эхо. `NO_ECHO` — нет питания с pin 16 или переключатель стоит не на «7».

## Подключение к Claude Desktop

Файл `%APPDATA%\Claude\claude_desktop_config.json` (*Settings → Developer → Edit Config*):

```json
{
  "mcpServers": {
    "mitsu-kkl": {
      "command": "C:\\Users\\USER\\AppData\\Local\\Programs\\Python\\Python313\\python.exe",
      "args": ["C:\\mitsu-kkl\\mcp_server.py"]
    },
    "mitsu-kkl-sim": {
      "command": "C:\\Users\\USER\\AppData\\Local\\Programs\\Python\\Python313\\python.exe",
      "args": ["C:\\mitsu-kkl\\mcp_server.py", "--iface", "sim:mutlive"]
    }
  }
}
```

Замените путь к `python.exe` на результат `where python`. После правки **полностью** перезапустите
Claude Desktop (через значок в трее). `mitsu-kkl-sim` — тренировка на симуляторе, без машины.
Другие варианты `--iface`: `auto` (по умолчанию), `d2xx:#0`, `serial:COM5`.

## Подключение к Claude Code

```
claude mcp add --scope user mitsu-kkl -- python C:\mitsu-kkl\mcp_server.py
claude mcp add --scope user mitsu-kkl-sim -- python C:\mitsu-kkl\mcp_server.py --iface sim:mutlive
claude mcp list
```

Можно и файлом `.mcp.json` в папке `C:\mitsu-kkl`:

```json
{
  "mcpServers": {
    "mitsu-kkl": {
      "command": "python",
      "args": ["C:\\mitsu-kkl\\mcp_server.py"]
    }
  }
}
```

Кабель держит только тот клиент, который вызвал `connect`. Если сервер запущен и в Desktop, и в Code,
второй получит ошибку открытия порта, пока первый не сделает `disconnect`.

## Инструменты

| инструмент | что делает |
|---|---|
| `cable_info` | интерфейсы (FTDI D2XX, COM-порты), ничего не отправляет |
| `selftest` | эхо и break-петля: запитан ли кабель, слышит ли он K-линию (только без сессии) |
| `connect(init=auto\|mut00\|obd33\|mut01)` / `disconnect` / `status` | сессия с ЭБУ; `auto` пробует 0x00, 0x33, 0x01. При неудаче ошибка говорит, кто виноват: кабель (нет эха) или ЭБУ (эхо есть, ответа нет) |
| `read_pids(pids, samples, interval_ms)` | сырые значения, пересчёт из профиля Colt и рядом `hypothesis` (значение по гипотезе, норма, источник); пары `29+2A`, `80+81` читаются вместе как 16 бит |
| `mutdump(note)` | все `00–BF` и `FD–FF` один раз → `logs\<время>_mutdump_mcp_<note>.json` |
| `diff_dumps(a, b)` | какие PID изменились, на сколько и какие биты переключились (читает и `.jsonl` от `kkl_probe`) |
| `record_start(pids, note)` / `record_stop` | CSV в формате `mut_gui` → `logs\<время>_readings_mcp_<note>.csv` |
| `analyze(file, mode, args)` | `tools/analyze_readings.py`: `summary`, `timeline ['21,17']`, `window ['26','34']`, `bits ['A8']`, `corr ['17']` |
| `dtc_read` | все байты-кандидаты в коды (`36–39`, `3B`, `3C`, `40–48`, `4A–4D`), разобранные по трём раскладкам (Eclipse, EvoEcu, MMCd) и двум порядкам битов — всё гипотезы |
| `defs_get(pid)` / `defs_set(pid, name, conversion, unit, confirmed, evidence)` | карта PID этого Colt; без `confirmed=true` к имени добавляется `?` |
| `list_logs` | файлы в `logs\`, сначала новые |

Профиль `profiles\colt_cj4a_md353925.csv` в том же формате, что `pid_definicje.csv`: его можно открыть
в `mut_gui` (*Load definitions*).

**`init=mut01`.** На части машин ЭБУ мотора будится адресом 0x01, а не 0x00 (EvoEcu MUT_Protocol). На других
машинах 0x01 — это блок АКПП. Поэтому при подключении через 0x01 `status` выдаёт предупреждение, а `mutdump`
отказывается работать, пока ID не сравнён с ответом на 0x00. Одиночные `read_pids` работают.
`status.fd` — ответ на `FD` (на Evo это `20`): ещё одна метка, по которой узнаётся ЭБУ.

## Гипотезы и нормы (`profiles\colt_hypotheses.csv`)

Это **не** карта Colt, а подсказки, которые нужно проверить. Сервер этот файл только читает. Источник указан
в каждой строке: **E** = EvoEcu MUT_Requests (Evo), **S** = EvoScan (пометки для 1998+), **M** = MMCd (1990–94),
**L** = выдержки из мануала Lancer '99, группа 13A, мотор 4G9 (целиком прочитать не удалось), **A** = Eclipse автора.
Подтверждённое переносите в профиль через `defs_set`.

Нормы на прогретом холостом (80–95 °C, N/P, кондиционер выключен). Номера запросов взяты из гипотез:

| что | запрос | формула | норма |
|---|---|---|---|
| обороты | `21` | x·31,25 | 700–800 (мануал: 750 ± 50) |
| целевые обороты ХХ | `24` | x·7,8 | ≈750 |
| шаги регулятора ХХ | `16` | x | 2–25 |
| время впрыска | `29+2A` | (256·29 + 2A)/1000 мс | 1,7–2,9 мс |
| расход воздуха (Карман) | `1A` | x·6,25 Гц | 25–51 Гц; 80–120 на 2500 об/мин |
| ОЖ | `10` | x−40 °C | 80–95 |
| воздух на впуске | `11` | x−40 °C | ≈ температура улицы |
| ДПДЗ закрыт | `17` | сырое | ≈27–37 (0,535–0,735 В) |
| бортсеть | `14` | x·0,0733 В | 13,5–14,5 на заведённом |
| барометр | `15` | x·0,49 кПа | 95–103 |

## Как составлять карту PID для Colt

Правила: **одно изменение за раз**, записывайте время каждого действия, зарядное устройство от АКБ
отключено (оно сдвигает напряжения). Что не подтверждено логом, сохраняется как гипотеза
(`confirmed=false`, имя с `?`). В `evidence` указывайте файл, время и значения. Лямбды нет, поэтому
PID коррекций и зонда с Eclipse (`0C–0F`, `13`) на Colt, скорее всего, ничего не покажут. Это тоже нужно
проверить, а не предполагать.

1. **Холодный дамп.** Машина простояла ночь. Зажигание включено, двигатель не запущен:
   `mutdump("cold, ign on, engine off, outside +8C")`. Запишите `FE/FF` (ID ЭБУ).
2. **Прогрев.** Запустите двигатель. На прогреве каждые 2–3 минуты делайте `mutdump("warmup +N min")`,
   пока не включится вентилятор. Либо `record_start` на 30–60 PID из `00–3F` с заметкой.
3. **Горячий дамп.** Двигатель прогрет, заглушен, зажигание включено: `mutdump("hot, ign on, engine off")`.
   `diff_dumps(холодный, горячий)` даёт кандидатов в температуру ОЖ (сырой АЦП NTC при нагреве **падает**)
   и другие медленные величины.
4. **Дроссель при заглушенном двигателе.** Зажигание включено, `record_start([...кандидаты...], "throttle sweep")`.
   Три раза медленно нажмите педаль 0 → до пола → 0, отметьте время, затем `record_stop`.
   `analyze(..., "summary")`, `corr` по найденному PID, `bits` по байтам флагов: там ищите датчик положения дросселя
   и флаг «дроссель закрыт».
5. **Отключение датчиков по одному.** Каждый разъём снимайте и ставьте **только при выключенном
   зажигании**. Порядок:
   `mutdump("before <датчик>")` + `dtc_read` → зажигание выключить → снять разъём → зажигание включить,
   подождать 10 с → `mutdump("<датчик> unplugged")` + `dtc_read` → `diff_dumps`.
   PID, который ушёл к краю (около 0 или около 240–255), — сырой сигнал этого датчика. Новый бит в байтах кодов
   (`dtc_read`) проверяет раскладку кодов: посчитайте мигания «check engine». Перебирайте датчики, которые реально стоят
   на моторе (ОЖ, температура воздуха, ДПДЗ, датчик воздуха…).
   Не замыкайте линию 5 В и не вешайте лампы как нагрузку: у автора лампа 2 Вт посадила питание 5 В датчиков.
   Нужна нагрузка — берите резистор 1–3 кОм и только на сигнальный провод. Коды после теста на этом
   ЭБУ, скорее всего, стираются отключением АКБ: через MCP стирания нет.
6. **На работающем двигателе** (P, ручник, проветриваемое место): обороты на холостых сравните с тахометром,
   затем по одному с записью — кондиционер, фары, обогрев стекла, вентилятор, руль до упора,
   селектор P → R → N → D на тормозе. Сначала смотрите байты флагов из гипотез: `record_start` на
   `00, 02, 49, 9A, A2, A8, AA, B3, B4, B8`, затем `analyze(..., "bits", ["00,02,A8,B3,B4,B8"])`:
   - селектор: P/N в `02` (маска 0x20, MMCd) или P/R/N/D в `B4` (0x40/0x80) и `B3` (0x01/0x02), передачи в `A8`.
     Если ничего не шевелится, возможно, коробкой управляет отдельный блок. Это тоже результат, его стоит записать;
   - кондиционер: `02` (0x10), `B8` (0x01), реле `49` (0x04), муфта `9A` (0x01) или `00` (0x20);
   - руль до упора (гидроусилитель): `02` (0x08) или `B8` (0x04); тормоз: `AA` (0x10);
   - импульсы `A2` (коленвал 0x01, ДМРВ 0x02, распредвал 0x04) на заведённом моторе должны мигать.
7. **Угол зажигания с разъёмом базовой установки.** Двигатель прогрет, на холостых. Замкните на массу разъём
   установки базового угла зажигания (по мануалу, отдельный разъём в моторном отсеке): ЭБУ фиксирует 5° до ВМТ.
   `record_start(["04","06","21"], "timing connector")`: если `06` встанет на сырое 25, формула x−20
   подтверждена (если на 15, то x−10, как у ЭБУ 1990–94). Разъём потом разомкните.
8. **Коды.** После отключения датчика `dtc_read` покажет, какой байт и какой бит загорелись. Это сразу
   определяет, какая раскладка ваша (`layouts`), и подтверждает код миганиями «check engine».
9. **Запись результата:** `defs_set("10", "coolant temp", "x-40", "°C", confirmed=false, evidence="dump cold/hot ...")`.
   Подтверждённым (`confirmed=true`) PID становится только после повторяемого теста.

Логи лежат в `logs\` (вне git). Профиль и журнал изменений лежат в `profiles\`, их стоит коммитить.
